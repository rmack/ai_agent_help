# Phase 2: Pattern Discovery

## Purpose

Find existing repository patterns before designing the enhancement.

## Ask / Inspect

1. What existing files/modules are related?
2. What naming, structure, validation, testing, or error-handling patterns exist?
3. Is there an existing similar feature?
4. Are there poor local patterns that should be treated as technical debt, not precedent?

## Produce

- relevant files/modules
- existing patterns
- patterns to follow
- patterns to avoid
- likely tests

## Stop / Continue

Ask whether to revise pattern understanding or continue to design impact.
